Founders Office · Going live checklist

Publish the repo, the app & turn on auto-updates

Everything's already wired in the code. This is the one-time "go live" run. After this, each future release is just 3 quick steps (Phase 5).

🖱️ Web clicks — anyone can do ⌨️ One-line command — you or your engineer ⏱️ ~30–45 min, once
1

Create the GitHub home for your app

🖱️ ~5 min
1

Sign in to GitHubweb

Go to github.com. If your company doesn't have an account yet, create one (free). Your company org is likely "bookr" — use that if it exists.

2

Create a new repositoryweb

Click New repository. Name it something like founders-office. Set it to Public — this is what lets each app fetch its updates freely. (Public means the download files are reachable; you do not have to put your source code here.) Click Create.

Write down two things from the address bar: the owner (e.g. bookr) and the repo name (e.g. founders-office). You'll need them in Phase 3.
3

Create an upload keyweb

This lets your computer post new versions to that repo automatically. Go to github.com/settings/tokens → Generate new token (classic) → tick the repo box → Generate. Copy the long code it shows and keep it safe — that's your upload key (it's shown only once).

2

Turn on Apple "notarization"

🖱️ ~10 min
1

Why this mattersinfo

Your app is already signed with your Apple identity. Apple also wants each new version "notarized" (a quick automated safety check), or Macs will quietly refuse to install the update. Windows needs none of this.

2

Get an app-specific passwordweb

Sign in at appleid.apple.com → Sign-In & Security → App-Specific Passwords → create one (call it "app updates"). Copy it. This lets the build talk to Apple safely.

3

Flip the switch in the app's settings1 line

In desktop/package.json, under "mac", change "notarize": false to "notarize": true. (Your engineer changes one word; your Apple Team ID QFH65RZ2JG is already in the file.)

3

Point the app at your repo

⌨️ ~2 min
1

Fill in the two blanksedit file

In desktop/package.json, find the "publish" section and replace the two placeholders with what you wrote down in Phase 1:

// desktop/package.json → build → publish
"publish": [
  {
    "provider": "github",
    "owner": "bookr",          ← your owner
    "repo":  "founders-office"  ← your repo name
  }
]
4

Publish the first version

⌨️ ~10 min
1

Give the build your keys, then run one commandterminal

In Terminal, paste your three secrets (from Phases 1 & 2), then run the build. It packages Mac + Windows and uploads them to a draft release on GitHub:

# paste your secrets (from Phases 1 & 2)
export GH_TOKEN=your-github-upload-key
export APPLE_ID=you@appleid.com
export APPLE_APP_SPECIFIC_PASSWORD=the-apple-password
export APPLE_TEAM_ID=QFH65RZ2JG

# build Mac + Windows and upload
cd desktop && npm run dist:all -- -p always
This runs on a Mac (Apple signing only works on macOS). It takes a few minutes and prints a lot — that's normal. Wait for it to finish.
2

Click "Publish" on the draftweb

Go to your repo → Releases. You'll see a draft release (version 0.3.1) with the Mac and Windows files attached. Review it, then click Publish release. That's the app live.

The download link you share with new users is on this Releases page — the .dmg for Mac, the .exe for Windows.

✅ Auto-updates are now live

From now on, anyone running your app will quietly pull each new version you publish — on Mac and Windows — with zero action from them or you beyond publishing.

5

Every future update — ~2 minutes

⌨️ repeat
1

Bump the version numberedit file

In desktop/package.json, raise "version" (e.g. 0.3.1 → 0.3.2). This is the signal that says "something new."

2

Run the same build commandterminal

Same secrets already set (or re-paste them), then:

cd desktop && npm run dist:all -- -p always
3

Click Publishweb

Publish the new draft release on GitHub. Done — every installed app updates itself from there.
