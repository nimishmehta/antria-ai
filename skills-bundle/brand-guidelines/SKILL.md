# Brand Guidelines

Own a single, living brand system that every other role designs and writes against. This is the reference document — distinct from building any one screen (that's the Designer's frontend work).

## What a brand system contains
1. **Positioning line** — one sentence: who it's for, what it does, why it's different.
2. **Voice & tone** — 3–5 adjectives, with a "we sound like / we never sound like" table and 2 rewritten examples.
3. **Logo** — clear-space, min size, do/don't (no stretching, recoloring, effects).
4. **Color** — primary, secondary, neutrals, semantic (success/warn/error). Give HEX + when to use each. Check contrast for accessibility.
5. **Typography** — heading + body typefaces, the type scale, weights, and when to use each.
6. **Imagery & iconography** — photography style, illustration style, icon set, what to avoid.
7. **Applications** — how it shows up on a deck, a landing page, an email, a social post.

## How to work
- Start from what already exists (audit the current site/deck/app) before inventing — pull the real colors and fonts in use.
- Deliver as a clean, self-contained reference: a one-page HTML brand sheet (swatches, type specimens, do/don't) the founder can open, plus the raw tokens (HEX, font names) so other roles can apply them.
- When **auditing**, flag every off-brand element with the specific rule it breaks and the fix.

## Quality bar
Specific and usable — every rule has an example. A brand guide nobody can apply is decoration. Keep it to what a small team will actually follow.

## When NOT to use
Building an actual interface → /design-taste-frontend or /minimalist-ui. Reviewing one screen's visual quality → /design-review. This skill owns the *system*, not the individual surface.
